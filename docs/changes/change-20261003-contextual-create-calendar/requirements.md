# Requirements

Given an explicitly selected visible Action in any view, Add creates its ordinary active child using its own Project and the exact direct Tag occurrence where applicable. Terminal parent lifecycle and dates remain unchanged. Selected Project/Tag nodes create directly classified root Actions; no current selection creates an unassigned root. Filters never manufacture assignments or dates, and Active-hidden views still allow Add. The new record is temporarily revealed for editing and remains reachable through its generated ID after navigation.

Header Project/Tag creation opens the corresponding tree and creates a distinct blank record. Same-view visible catalog or Action occurrence supplies its parent; cross-view invocation creates at root. Name gets focus only while invocation selection/navigation still matches. Unknown results retain the exact request and typed generated identity.

Due and Defer both provide native date selection and explicit 24-hour text time. New date defaults09 in the explicit client zone; complete numeric input normalizes, partial input does not. Seconds/milliseconds, DST rejection, raw incomplete proposals, newer IME input and saved UTC instants are preserved. Clear Due means null; deliberate clear Defer means release.

Counterexamples: filter inference, inherited Tag propagation, parent reopening, stale reply focus stealing, permanently changing projection filters, invented catalog names, partial clock converted to09 or null, and locale-dependent12-hour clocks are invalid.
